# Phase 2B Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A lightweight responsive web console over the existing task backend, signed in with Slack, where a change made on the web writes to the same database Slack uses and redraws the Slack card it came from.

**Architecture:** `apps/web` is a Next.js App Router app whose server code imports `@tr/task-core` directly, so a button calls the same `completeTask` the Slack checkbox calls. No business logic in the browser and no internal HTTP hop. Card drawing moves out of `apps/slack` into `packages/slack-sync` so both apps share one copy.

**Tech Stack:** Next.js (App Router, Server Actions) · TypeScript strict · Auth.js with the Slack provider · Vitest against PGlite · Supabase Postgres on Vercel

**Spec:** `docs/superpowers/specs/2026-09-10-web-ui-design.md`

## Global Constraints

- The web UI holds no business logic. Every task read goes through `task-core` query functions; every task write goes through a `task-core` mutation. No SQL in `apps/web` except through those.
- `editTask` remains the only title write path. Title editing on the web is an explicit form submission — never inline-on-blur, never autosave.
- Authorization keys on the Slack user id against `AUTHORIZED_SLACK_USER_IDS`. **An empty allowlist denies everyone.** Every page and every server action re-checks the session.
- The development bypass requires BOTH `NODE_ENV !== 'production'` AND `WEB_DEV_USER` to be set.
- `cookies()` and `headers()` are async in the App Router — always awaited.
- Auth.js env names are fixed: `AUTH_SLACK_ID`, `AUTH_SLACK_SECRET`, `AUTH_SECRET`. The Slack redirect URL is `/api/auth/callback/slack` and **must be https, even locally**.
- A Slack redraw failure must never roll back or lose a task change. Task write first, redraw after, errors caught and logged.
- Settings renders no credential. Nothing beginning `xox`, `xapp-`, `sk-`, or containing `postgres://` may reach a response.
- Filters are URL query parameters, resolved in SQL through `listTasks` — never by filtering a full dump in the browser.
- Readable at 375px with no horizontal scrolling.

```ts
/**
 * Redraws every recorded Slack card containing this task.
 *
 * Called after a web mutation. Errors are caught per card and counted, never
 * thrown: the task write has already committed, and a Slack outage must degrade
 * the card rather than lose the change.
 */
export async function syncCardsForTask(
  deps: CardDeps, taskId: string
): Promise<SyncResult> {
  const { rows } = await deps.db.query<{ channel_id: string; message_ts: string }>(
    `SELECT channel_id, message_ts FROM slack_cards
      WHERE $1 = ANY(task_ids) ORDER BY updated_at`,
    [taskId]
  );

  let cards = 0;
  let failed = 0;
  for (const row of rows) {
    try {
      await withCardLock(`${row.channel_id}:${row.message_ts}`, async () => {
        const card = await loadCard(deps.db, row.channel_id, row.message_ts);
        if (!card) return;
        await redrawCard(
          deps, row.channel_id, row.message_ts, card.task_ids, card.view_scope
        );
      });
      cards += 1;
    } catch (err) {
      failed += 1;
      console.error(
        `[slack-sync] could not redraw ${row.channel_id}/${row.message_ts}`, err
      );
    }
  }
  return { cards, failed };
}
```

```ts
/** Same allowlist apps/slack enforces, so there is one answer to who may act. */
export function authorizeSlackUser(
  slackUserId: string | null | undefined,
  env: NodeJS.ProcessEnv = process.env
): boolean {
  if (!slackUserId) return false;
  const allowed = (env.AUTHORIZED_SLACK_USER_IDS ?? '')
    .split(',').map((s) => s.trim()).filter(Boolean);
  // Fail closed. The Slack app can fall back to a workspace check; the web app
  // cannot, because Auth.js does not document the Slack profile's shape, so an
  // empty list must deny rather than admit.
  if (allowed.length === 0) return false;
  return allowed.includes(slackUserId);
}

/**
 * Local sign-in bypass. Slack requires an https redirect even in development,
 * so signing in on localhost is impossible without a tunnel.
 *
 * Both conditions are required, and a test asserts this is inert in production.
 */
export function devUser(env: NodeJS.ProcessEnv = process.env): WebUser | null {
  if (env.NODE_ENV === 'production') return null;
  const id = env.WEB_DEV_USER?.trim();
  if (!id) return null;
  return { slackUserId: id, name: 'Local development user' };
}
```

`currentUser` reads `devUser()` first, then the Auth.js session, and returns null
unless `authorizeSlackUser` passes. `requireUser` calls `redirect('/signin')`
when it returns null.

let cached: Promise<Db> | null = null;

export function getDb(): Promise<Db> {
  cached ??= (async () => {

  })();
  return cached;
}

- [ ] **Step 3: Implement**

Each action follows one shape:

```ts
async function withUser<T>(
  fn: (db: Db, user: WebUser) => Promise<T>
): Promise<ActionResult> {
  const user = await currentUser();
  if (!user) return { ok: false, error: 'not authorized' };
  const db = await getDb();
  try {
    await fn(db, user);
    return { ok: true };
  } catch (err) {
    if (err instanceof InvalidTaskIdError) return { ok: false, error: 'unknown task' };
    if (err instanceof TaskNotFoundError) return { ok: false, error: 'unknown task' };
    if (err instanceof UnknownSpaceError) return { ok: false, error: err.message };
    throw err;
  }
}
```

After a successful mutation the action calls `syncCardsForTask` inside its own
try/catch and then `revalidatePath('/')` plus the current path, so the list
re-renders. The sync's failure is logged, never surfaced as a failed action.
